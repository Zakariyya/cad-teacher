# 项目结构与维护设计

本项目是一份持续编写、按学习反馈调整的入门到进阶教材。当前仅第一课完成，不把课程路线冒充已写完或已达到“精通”。

## 目录职责

```text
README.md                    阅读入口
AGENTS.md                    仓库协作与教学约定
prompts/                     原始需求、项目指令、恢复学习提示词
curriculum/                  分阶段路线与能力检查
learning/                    课程、练习反馈、进度与固定交付路径
  lesson-01.*                保留已有课程与产物路径
  lesson-01-review.md         真实作答与反馈
  progress.md                学习状态唯一入口
  chatgpt-study-pack.txt       自动生成的网页端上传包
resources/                   来源索引、固定版本和许可信息
  skill-sources.json         上游提交、Skill 路径、快照 blob 哈希
  skills.md                  可点击的 Skill 来源目录
  vendor/baratilab/          起步课最小许可快照
templates/                   新课、反馈和验证记录模板
tools/                       学习包生成与仓库检查
docs/                        网页端使用、教学质量和维护说明
```

## 路径和版本规则

- 保留第一课与 `learning/` 主交付路径，不因本次结构升级搬迁旧文件。
- 新课按 `lesson-NN.md`、`lesson-NN-review.md`、`lesson-NN.py` 命名；复杂课可在 `learning/lesson-NN-assets/` 保存配套模型与图。首次确定后保持稳定。
- `learning/progress.md` 记录唯一的当前课、已掌握/待巩固内容、下一步。课程路线只写阶段检查目标，不重复维护个人完成状态。
- 原始提示词独立保存，不把后续调整混入原文。调整写入项目指令和版本记录。
- 上传包由源文件生成，禁止手改；源文件变更后重新生成并检查。
- 新课必须加入 `curriculum/lessons.json`（内容发布登记，不是个人掌握状态）。先设 `feedback_published: false`；作答和反馈完成后才改为 true，登记反馈、解析脚本与答案。上传包自动收录讲义及示例，只在明确公开反馈后收录解析。个人状态仍只在 progress.md 维护。
- `example_script` 只能包含公开教学示例，不得混入待答习题答案；含答案的脚本放在 `solution_script`。模板中的练习题面不得嵌入答案。需要事先保存但未公开的答案应留本地；本仓库是公开仓库，上传包不收录不等于 GitHub 文件不可见。
- 新课后同步检查进度是否对应已登记内容，再按模板补资源与验证；不要自动生成未开始课程的“已完成”状态。
- 原创文本读写使用 UTF-8，仓库用 `.gitattributes` 固定 LF，避免跨设备导致第三方快照哈希改变。
- 第三方源码不混入原创目录，保留版权及许可；上游更新需明确提交 SHA，不无声替换已用于教学的资源。

## 本次执行计划与完成标准

1. 核实两个上游仓库、Skill 实际路径和提交 SHA，生成来源登记表。
2. 保存原始提示词及网页端教学/恢复指令；建立课程路线与质量规范。
3. 原路径保留第一课，补齐来源、固定版本和可上传资源。
4. 用标准库生成学习包、校验本地链接和来源快照哈希，运行第一课计算。
5. 独立审阅结构与可迁移性，修复问题后使用中文提交并推送。

验收：来源可追溯；无本机绝对路径依赖；已完成与计划内容明确区分；包可重建且未过期；习题不提前泄露；无虚构网页、仿真或实物验收；远端提交与本地一致。
